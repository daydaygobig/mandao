# infosop-card · 提问前置信息卡

一个**单文件 HTML 表单**，用于工作咨询群提问前填写关键背景信息。

核心目的只有一个：**堵住「海龟汤」** —— 提问的人有意无意漏掉一部分信息，回答的人只能一路猜，猜到最后发现前提全错，前面聊的全白费。

---

## 它解决什么问题

职场问题从来不是单变量问题。一个人问「这个 offer 值不值」，如果他没说自己已经裸辞半年、家里还在催，那么所有基于「在职跳槽」给出的建议都是错的。

**事物是普遍联系的，你隐藏的那一项，往往就是别人判断错的原因。**

所以这张卡把实践中反复吃亏总结出来的、真正影响结论的变量，全部前置问清楚：

| 章节 | 问什么 | 为什么问这个 |
|---|---|---|
| 0 | 发红包没 | 群礼节 |
| 1 | 性别、性取向、年龄、婚姻状态 | 决定问题的基本盘 |
| 2 | 城市（现在/将来/能接受）、工作经历、收入、存款、房产 | 城市是四种活法，不能用一个「一线」概括 |
| 3 | 家庭背景、老家、兜底能力、父母、兄弟姐妹、宠物 | 生活结构与托底能力 |
| 4 | 身体健康、身高体重、发烧情况、家族遗传病 | 硬约束 |
| 5 | 学历（自己/伴侣） | 写到「层次 + 专业」 |
| 6 | 家里赌狗、追星打赏、被诈骗 | 钱被打水漂的三条路径 |
| 7 | 信仰 | |
| 8 | 是不是本人提问 | 区分本人和代问 |

## 设计原则

### 1. 手填优先于选项

**判断标准：信息是否有唯一标准答案 / 选项是否帮助填写人隐藏信息。**

大部分字段都做成了手填文本框，而不是选项按钮。原因很直接——选项会**帮助填写人隐藏信息**。

举个典型例子：

- 下拉框选「一线城市」 → 只知道城市等级，不知道他在这座城市有没有根
- 手填「深圳，外地来的，待了 5 年」 → 立刻能判断他是选择留下还是只能留下

再比如「遗传病」，原来给的是「没有 / 有 / 不清楚」三个按钮。但「父亲 65 岁高血压」和「母亲 40 岁乳腺癌」在按钮上都是同一个「有」，而这两件事对下一代的意义完全不同。

### 2. 说明文字在输入框上方，且与字段名有明确视觉层级

- 字段名：14px，深色 `#1B1B1B`，600 粗
- 说明文字：12px，浅色 `#A8A29A`，400 细 + 左侧竖线

避免填写人把说明和字段名混在一起。

### 3. 提示即判据

说明文字不只是「怎么填」，更要给出**判断依据**。例如发烧那一栏：

> 一年一两次、有明确原因（受凉、流感）属正常；一年多次、反复不明原因发烧，多半是家里防疫或环境出了问题，要具体写。

### 4. 不重复问同一件事

每个信息只有一个归属字段。城市栏只问「和这座城市的关系」，户口、房、钱分别由各自的字段回答——**同一个问题在两处问，答案必定打架**。

### 5. 宽容判定，宁可多提醒

回溯列表的风险标签（⚠️有赌狗 / ⚠️追星打赏 / ⚠️被诈骗过）用正则匹配多种「没有」的写法，避免填「无」被误标；但只要有风险内容就一定会标出来。

## 使用方式

### 直接打开

```
index.html
```

单文件，零依赖，双击即可在浏览器打开。填完点「生成信息卡」，会生成文字版，复制粘贴发群里即可。

### 部署

任意静态托管都可以，无需构建：

- GitHub Pages：Settings → Pages → Source 选 `main` 分支根目录
- 或丢到任意 web 服务器 / 对象存储

### 数据存储

所有数据只存在**浏览器 localStorage**，7 天后自动清除。没有任何后端、没有网络请求、不上传任何服务器。

「回溯」标签页用来按昵称搜索本机填写过的记录。

---

## 技术说明

- **单文件**：HTML + CSS + JS 全在 `index.html` 内，无打包、无压缩、无依赖
- **无后端**：纯静态，所有逻辑在浏览器端
- **移动端适配**：390px 宽度下正常显示
- **零依赖**：不需要 npm、不需要构建工具
